# Evals · the real test suite

The brain is scored against scripted situations with expected decisions. This is the project's primary test suite; unit tests are kept lean (see `CLAUDE.md`). The eval harness runs headless in Node against the brain package. The brain is deterministic and has no network, so the suite is exact.

## 1. Format

```
packages/evals
  scenarios/
    hungry.walk.json          the full walk as a sequence of snapshots (generated by the sim in record mode)
    errands.walk.json
    walking.walk.json
    gates/*.json              short, focused cases: crossing, bike, conversation, budget empty
    notifications/*.json      text at a light, DM in a crossing, social accumulation, call during a walk
    moments/*.json            pace to signal, bus, which stairs (whisper), closed early, sidewalk closed, bike
    walking/*.json            one case per walking rule: focus zone per band, reading budget, auto-fold, peripheral entry, head scan, pocket save, pocket surface, right of way, backdrop, dwell ladder, whisper, snooze, budget
  expectations/
    *.expect.json             what the brain must and must not do, keyed by walk and time window
  run.ts                      runs every case, scores, writes a report
  report/                     JSON and a small HTML page; the inspector reads the JSON
```

An expectation:

```json
{
  "walk": "hungry",
  "cases": [
    { "between": [74, 84], "must": { "action": "hold", "all": true, "reasonKind": "gate" } },
    { "between": [84, 88], "must": { "action": "show", "id": "order-ready", "level": "glance", "reasonText": "Held that while you crossed" } },
    { "between": [0, 10], "mustNot": { "level": "card" } },
    { "between": [0, 90], "max": { "shows": 9 } },
    { "between": [37, 58], "must": { "band": "brisk", "levelsAtMost": "whisper" } },
    { "between": [22, 23], "must": { "action": "save", "id": "mega-burger" } },
    { "between": [60, 63], "must": { "action": "surface", "secondsAtLeast": 6 } },
    { "always": { "focusZoneClear": true, "reasonCites": ["goal", "world", "gate", "budget", "social", "edge", "pace", "pocket"] } }
  ]
}
```

### Cases and expectations, as built

A case file (`scenarios/{gates,notifications,moments,walking}/*.json`) is a compact script the runner expands into 10 Hz snapshots (`synthesize` in `packages/shared/src/synth.ts`): a scenario, a duration, a start position, and timed tracks for speed, gaze, pinch, choice, dismiss, pitch, yaw, crossing, signal phase, inbox, people, vehicles, live data, stops and sidewalk changes. A recorded walk (`scenarios/*.walk.json`) is the full snapshot sequence from `pnpm record`.

An expectation case is one of: `must` (some decision in the window matches; with `all: true`, every decision outside the ground layer matches), `mustNot`, `max` and `min` (`shows`, `nonGazeShows`, `holds`), `state` (every brain frame in the window matches: band, safety, snooze, glyph, has, hasNot, level per item, levelsAtMost, pocket) and `stateSome`. Windows are half-open `[from, to)`. Match fields: action, id, idPrefix, level, levelAtLeast, levelAtMost, reasonKind, reasonText, band, timing, zone, component, cause, gaze, secondsAtLeast, nameIs, factIs, factIncludes, showReason, enter, focusOk.

Every run, case or walk, is also checked against the global invariants in `src/invariants.ts`: reasons (kind, length, banned words), no em dash, gates, focus zone (from the overlay's pane rects in recorded walks), reading budget, auto-fold, peripheral entry, the pocket save and surface, the dwell ladder, whisper, snooze, budget and meter, hysteresis, message timing, nobody on the path, placement hints, and determinism (two runs, identical logs). Rules 5, 8 and 9 are geometry and light: their brain-side contract is a case here, and their measured check lives in the overlay's placement and legibility tests.

## 2. What is scored

- **Gates.** During any crossing or vehicle threat, every world-zone decision is a hold with `reasonKind: gate`. Zero tolerance.
- **Restraint.** Shows per walk never exceed the budget (7 plus refills); Just walking shows at most 4 non-gaze items (a show is a `show` at glance or above; pips and ground safety text do not count).
- **Timing.** Messages while walking are `next-pause`; a message during a gate is `after-gate` and surfaces at the curb with the follow-up line.
- **Levels.** The dwell ladder: no card without the band's dwell or a pinch in Stopped or Stroll; no expanded without 2 s more dwell or a pinch, and never above Stroll; never two cards; whisper only in Brisk; nothing but whisper in Brisk.
- **Walking rules.** Every rule in `docs/walking-rules.md` has its eval line; the `walking/` cases are the contract. A pinch in Walk or Brisk is a save, never a show. The pocket surfaces within 500 ms of a qualifying stop with the right remaining time and never under 6 s. No non-gaze glance persists past its band's auto-fold limit. The first frame of any pane while moving is outside the focus zone for its band.
- **Right of way and yielding.** In the scripted truck and passerby beats, no pane rect intersects the occluder rect above 30% opacity; in the head-scan beat the scanned side is below 20% within 200 ms and restored within 400 ms (these run in the overlay's placement tests on a fixed camera).
- **Legibility.** Primary text contrast at least 4.5:1 against the sampled backdrop at every scripted beat, lit and shadowed façades both.
- **Hysteresis.** No score-driven level change within 1.2 s of the previous one on the same item, except on a gate; dwell-ladder climbs and look-away descents are exempt. No band change within 600 ms of the previous one.
- **Reasons.** Every reason cites an allowed kind and never the wearer's body, eyes or habits (the banned-word list in `docs/copy.md` is checked: look, looked, looking, gaze, eyes, stared, glanced, habit, noticed you, walking fast, slow down, you were).
- **Placement hints.** Every show carries a zone, a preference and its band; the overlay's placement tests (in the overlay package) check the band's focus zone against rendered positions on a fixed camera.
- **Determinism.** Two runs of the same walk produce identical logs.

## 3. Running

`pnpm eval` runs everything and writes `packages/evals/report/latest.json` and `latest.html`. `pnpm eval --walk hungry` runs one. The build is not done while any gate case fails. The inspector's Evals panel reads `latest.json`.

## 4. Recording

`pnpm record --scenario hungry` runs the sim in Node with no renderer, driving the scripted reviewer, and writes the walk file. Re-record when a scenario script changes. Expectations are hand-written and reviewed; never generated.

As built: recording is deterministic and takes about two seconds for all three walks, so `pnpm eval` re-records the walks before scoring them (pass `--no-record` to score the files on disk). The walk files are build artifacts and are not committed; a walk file stores compact snapshots and the runner rehydrates each place's static copy from `data/places.json`.
