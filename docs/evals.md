# Evals · the real test suite

The brain is scored against scripted situations with expected decisions. This is the project's primary test suite; unit tests are kept lean (see `CLAUDE.md`). The eval harness runs headless in Node against the brain package. The brain is deterministic and has no network, so the suite is exact.

## 1. Format

```
packages/evals
  scenarios/
    hungry.walk.json          the full walk as a sequence of snapshots (generated by the sim in record mode)
    walking.walk.json
    gates/*.json              short, focused cases: crossing, bike, conversation, budget empty
    notifications/*.json      text at a light, DM in a crossing, social accumulation
    moments/*.json            pace to signal, bus, which stairs (whisper), sidewalk closed, bike
    walking/*.json            one case per walking rule: focus zone per band, reading budget, auto-fold, peripheral entry, head scan, pocket save, pocket surface, right of way, backdrop, dwell ladder, whisper, snooze, budget
  expectations/
    *.expect.json             what the brain must and must not do, keyed by walk and time window
  run.ts                      runs every case, scores, writes a report
  report/                     JSON and a small HTML page; the inspector reads the JSON
```

An expectation:

```json
{
  "walk": "hungry",
  "cases": [
    { "between": [74, 84], "must": { "action": "hold", "all": true, "reasonKind": "gate" } },
    { "between": [84, 88], "must": { "action": "show", "id": "order-ready", "level": "glance", "reasonText": "Held that while you crossed" } },
    { "between": [0, 10], "mustNot": { "level": "card" } },
    { "between": [0, 90], "max": { "shows": 9 } },
    { "between": [37, 58], "must": { "band": "brisk", "levelsAtMost": "whisper" } },
    { "between": [22, 23], "must": { "action": "save", "id": "mega-burger" } },
    { "between": [60, 63], "must": { "action": "surface", "secondsAtLeast": 6 } },
    { "always": { "focusZoneClear": true, "reasonCites": ["goal", "world", "gate", "budget", "social", "edge", "pace", "pocket"] } }
  ]
}
```

### Cases and expectations, as built

A case file (`scenarios/{gates,notifications,moments,walking}/*.json`) is a compact script the runner expands into 10 Hz snapshots (`synthesize` in `packages/shared/src/synth.ts`): a scenario, a duration, a start position, and timed tracks for speed, gaze, pinch, choice, choose (a place's row chosen in its expanded view: `{ t, id, row }`, the action being the place's primary one), dismiss, pitch, yaw, crossing, signal phase, inbox, people, vehicles, live data, stops and sidewalk changes. A recorded walk (`scenarios/*.walk.json`) is the full snapshot sequence from `pnpm record`.

An expectation case is one of: `must` (some decision in the window matches; with `all: true`, every decision outside the ground layer matches), `mustNot`, `max` and `min` (`shows`, `nonGazeShows`, `holds`), `state` (every brain frame in the window matches: band, safety, snooze, glyph, has, hasNot, level per item, levelsAtMost, pocket) and `stateSome`. Windows are half-open `[from, to)`. Match fields: action, id, idPrefix, level, levelAtLeast, levelAtMost, reasonKind, reasonText, band, timing, zone, component, cause, gaze, secondsAtLeast, nameIs, factIs, factIncludes, showReason, enter, focusOk.

Every run, case or walk, is also checked against the global invariants in `src/invariants.ts`: reasons (kind, length, banned words), no em dash, gates, focus zone (from the pane rects in recorded walks, which the recorder produces by running the overlay's own `Placement` and `Aside` per item at 60 Hz with the same keep-outs as the live glasses), reading budget, auto-fold, peripheral entry, the pocket save and surface, the dwell ladder, whisper, snooze, budget and meter, hysteresis, message timing, nobody on the path, placement hints, and determinism (two runs, identical logs). Rules 5, 8 and 9 are geometry and light: their brain-side contract is a case here, and their measured check lives in the overlay's placement and legibility tests.

## 2. What is scored

- **Gates.** During any crossing or vehicle threat, every world-zone decision is a hold with `reasonKind: gate`. Zero tolerance.
- **Restraint.** Shows per walk never exceed the budget (7 plus refills); Just walking shows at most 4 non-gaze items (a show is a `show` at glance or above; pips and ground safety text do not count).
- **Timing.** Messages while walking are `next-pause`; a message during a gate is `after-gate` and surfaces at the curb with the follow-up line.
- **Levels.** The dwell ladder: no card without the band's dwell or a pinch in Stopped or Stroll; no expanded without 2 s more dwell, or a pinch in Stopped or Stroll, and never in Brisk; never two cards; whisper only in Brisk; nothing but whisper in Brisk.
- **Walking rules.** Every rule in `docs/walking-rules.md` has its eval line; the `walking/` cases are the contract. A pinch in Walk or Brisk is a save, never a show. The pocket surfaces within 500 ms of a qualifying stop with the right remaining time and never under 6 s. No non-gaze glance persists past its band's auto-fold limit. The first frame of any pane while moving is outside the focus zone for its band.
- **Right of way and yielding.** In the scripted truck and passerby beats, no pane rect intersects the occluder rect above 30% opacity; in the head-scan beat the scanned side is below 20% within 200 ms and restored within 400 ms (these run in the overlay's placement tests on a fixed camera).
- **Legibility.** Primary text contrast at least 4.5:1 against the sampled backdrop at every scripted beat, lit and shadowed façades both.
- **Hysteresis.** No score-driven level change within 1.2 s of the previous one on the same item, except on a gate; dwell-ladder climbs and look-away descents are exempt. No band change within 600 ms of the previous one.
- **Reasons.** Every reason cites an allowed kind and never the wearer's body, eyes or habits (the banned-word list in `docs/copy.md` is checked: look, looked, looking, gaze, eyes, stared, glanced, habit, noticed you, walking fast, slow down, you were).
- **Placement hints.** Every show carries a zone, a preference and its band; the overlay's placement tests (in the overlay package) check the band's focus zone against rendered positions on a fixed camera.
- **Choices.** `moment-choose-row` holds the cinema's expanded view to four films with the action reading for 8:00, then a choice on the 7:15 row leaves that row alone with its confirmation logged on the choice (cause `choice`), counts it in the pocket (`Pocket 1`), and does not surface the pocket at that stop. Expectation matchers `rowsAre` and `actionsAre` compare a decision's row titles and action labels.
- **The door.** The Lunch recording ends on the Big Bean: its expanded view by 1:56 with the four rows and the action reading Order ahead, the Cortado chosen at 1:57.5 leaving that row with `Cortado ordered · ready at 12:46, skip the line.` on a cause-`choice` decision, `Pocket 2` at the end, and the loop resuming once the look lets go. Since Phase 29 the Lunch recording also checks the owner's two rules there: the Big Bean's expanded view opening at Walk on the approach at 1:46, coming down to the arrival line when it comes into sight at the door unlooked at, and the view at its label by 2:00.0 after the look is released at 1:59.5; the Trattoria's view opening at Walk 2 s after its card at 0:41.8 while the pinch at 0:41 opens nothing. Live, `pnpm doors` (`scripts/doors.ts`) is the door's check: it visits all 14 places through the menu in one walk (`--laps 2` twice), holds the look at each door, turns the head across the rows with the viewfinder (the pointer never rests on a row), pinches with Enter, and fails a place when its expanded view is on the glass at full opacity for less than 90% of the stop, opens later than 3 s after arriving, a row of choices does not lift under the look, or the choice brings no confirmation. `scripts/cardplay.ts` fails on the same terms for the pointer.
- **Walk expands, looking away shrinks.** `walking-10b-dwell-ladder-walk`: a held look at Walk reaches the compact card at 1.8 s, the full card as the place comes within 30 m at 2.4 s, the expanded view 2 s later, its card half a second after the look leaves and its label a tick later; a unit case holds an expanded view with the look 30 px outside its rect to its card at `lookAwayS` (0.5 s) and its label a tick later, and keeps it with the look inside, and another climbs nothing while the head turns; `walking-10c-look-away` has the view a label at 5.8 s, half a second after the look leaves its card at 5.3 s; the Lunch Trattoria's view is a label at 0:44.4 and the Explore theater's at 0:28.4.
- **The label under the look.** `walking-10h-label-under-look`: the look rests on the Trattoria's label and moves off just before the view settles again with its sign out of view; the label stays through the settle and leaves a second after the look, while Lucky Lanes, out of view and not looked at, leaves with the settle.
- **Places.** `places` also checks that a live line's tone is `go`, `warn` or `stop` and that a `warn` or `stop` line names its status after the interpunct, and that every expanded row has a key or a thumbnail, a title, a sub and a value.
- **The arrival is not budgeted.** `walking-13b-arrival-unbudgeted`: with the budget spent, Goldie's score label holds on it; at Goldie's door it comes up all the same, since the place the wearer asked to be taken to is never charged to the budget.
- **The door's trace.** `pnpm doors` writes the whole trace of every stop that fails (every 100 ms from the choice in the menu: the brain's level and anchor, the glass's level, visibility and opacity, the placement's mode, the hold, the look and its dwell, the mark, the keep-outs over the pane, then the brain's decisions and the overlay's log for the place) to `.cache/doors/<place>-lap<n>.txt` and names it on the line; `--keep` writes it for every stop.
- **Aim.** `pnpm aim` (`scripts/aim.ts`) plays four live laps of Explore at 1920 x 1080 (two until Phase 30 added the turn and rest after every card or view) and aims the way the owner does at Stroll and at Walk: it drags the viewfinder onto a label or a card the look is not on, steering by eye while the button is down, and lets go once the square holds the place or the pane is under the center, at least 40 times. One line per aim: the band, the place aimed at, the place the gaze holds 0.5 s after letting go, and any jump. It passes when the gaze holds the aimed place in at least 95% of aims and no looked-at pane moves more than 60 px in 100 ms while its light moves less than 20 px, a rule 8 step aside or return excepted; during a level change the corner the pane grows from (the view's edge, for a pane held against it) may not move more than 60 px in 100 ms either, unless the pane changed side for want of room. Every aim also prints its landing and its drag, and both must hold on every aim with no excuse: from the frame the look lands, for as long as the look stays, the aimed pane's offset from its light (its center to the light the overlay placed it against) changes under 2 px a frame and 6 px in all; while the pointer is down, the looked-at pane's offset from its light changes no more than 1 px a frame. After every aim that reaches a card or a view, the owner's move (Phase 30): one turn of 100 px (times `--ui`) off it, then 3 s of rest where the turn ended; it must leave the look off the place by the end of the turn, the pane a label on the brain within 0.75 s (the 0.5 s look-away and its two steps on the 10 Hz tick) and at its label's size on the glass by 1.6 s (the look-away and the 0.9 s descent), and the place not looked at again during the rest unless its light is inside the viewfinder (a place taken back that way is a look at it, and its card rightly stays, so the label is not required then); a look-away a safety gate interrupts is printed and not counted; printed per aim as `look-away:` and summed as `look-aways:`, every one required. A failing look-away prints the walk's look state (`Walk.lastTake`, the left list, the travel reference) and the brain's for the place. Every drag frame that fails prints the frame before and the frame of the failure (how the pane was drawn, its drawn rect, its light, its offset, its placement's rect and anchor factors, any step aside, its opacity), so a pin frame can be read from the log alone. Around every landing, from 0.5 s before it to 0.5 s after, no world pane within 300 px of the center moves more than 6 px against the world in a frame, for any reason and with no exclusion list; a pane changing size is judged at the corner it grows from, and a frame the browser dropped counts at its length; a failure prints the pane, its state (how it was drawn, its level on the glass and on the brain, `moved`, `why`, step aside, yield, jump) and the frame pair, and the count of pairs is summed. The near measure ("within 160 px of the center 3 s later") measured the pull and went with it in Phase 31. Every level change of a held pane prints how far its growth corner moved, and it must be under 60 px. An aim whose window runs into a crossing, or whose target a vehicle or a person hid under rule 8 while the wearer was still aiming, is not counted; every excuse is printed on its line.
- **The probes.** Three reviewer probes in `.cache/review/`, run with `npx tsx` against the dev server on 5199, play the moves the owner named in Phase 31. `cancel.mts 1.95`: a card held 1.97 s of its 2 s, then a quick turn off it: no `expanded` after the turn, and after the shrink no move over 6 px against the world in a 50 ms sample. `lookaway3.mts`: a view and a card turned off; from the first frame the drawn rect shrinks to the frame it reaches its label's size, at least 0.85 s for a view and 0.38 s for a card, no frame changing the width or the height by more than 8% of the pane's size at the start of the descent, and the children of the leaving level still drawn 100 ms into each step. `switch.mts 8`: hold one place, turn onto another label, recorded from before the pointer goes down: no one-frame move over 6 px, and every look landing on the pane the center reached. Options: `--until` (walk seconds, 660 for four laps), `--laps`, `--verbose` (the overlay's log and the light for every failure), `--trace` (every step of every drag), `--shots dir`.
- **One banner.** `note-two-texts`: a second text at a red light tucks under the first as a strip (sender and line), is never the banner while the first is up, and the banner's time reads `2 · now` (matcher `timeIs`).
- **The places.** A data suite (`places`, group `data`) checks every place in `data/places.json`, whether or not a walk shows it: every say line in every scenario under 60 characters, at most two numbers, never repeating the name, no banned word; every live line within 28 characters; every place with a depth one to four rows, one primary action, Not now and an after line for it (for each row where the rows are choices), Pocket Park by name with rows and no action. The data loader refuses more than four rows, or a row with an action label and no after line.
- **Determinism.** Two runs of the same walk produce identical logs.

## 3. Running

`pnpm eval` runs everything and writes `packages/evals/report/latest.json` and `latest.html`. `pnpm eval --walk hungry` runs one. The build is not done while any gate case fails. The inspector's Evals panel reads `latest.json`.

## 4. Recording

`pnpm record --scenario hungry` runs the sim in Node with no renderer, driving the scripted reviewer, and writes the walk file. Re-record when a scenario script changes. Expectations are hand-written and reviewed; never generated.

As built: recording is deterministic and takes about two seconds for all three walks, so `pnpm eval` re-records the walks before scoring them (pass `--no-record` to score the files on disk). The walk files are build artifacts and are not committed; a walk file stores compact snapshots and the runner rehydrates each place's static copy from `data/places.json`.
